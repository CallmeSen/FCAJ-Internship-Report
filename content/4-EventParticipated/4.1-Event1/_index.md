# Summary Report: "Cloud Architect"

### Event Overview

- **Event name:** Cloud Architect
- **Format:** Team-based quiz game show
- **Participants:** 8 teams, each team with 5 members
- **Topic:** AWS cloud knowledge, architecture design, and some AWS Solutions Architect Associate (SAA)-style questions
- **Registration:** [Google Form](https://forms.gle/Gi7Z6nod1bofZcxY7)
- **Team selection result:** 19 June 2026

### Event Objectives

- Create a new and engaging learning experience while keeping the spirit of sharing and studying
- Strengthen knowledge of **Cloud**, **AWS**, and **solution architecture design**
- Help participants review basic AWS architecture concepts through competitive questions
- Encourage teamwork, quick discussion, and confident decision-making under time pressure
- Practice risk management through special game skills
- Motivate interns to learn more about AWS Solutions Architect Associate (SAA) topics

### Event Format

- The event included **8 teams**, and each team had **5 members**
- Members did not need to be from the same internship group, but one person could not join more than one team
- Teams competed against each other in rounds
- Each match used question sets arranged from easy to difficult
- The team with the higher score advanced to the next round
- If both teams had the same score at the end, the tie-breaker used **question 10 from an unused question set**
- In this tie-breaker, the team that answered faster won the match

### Key Highlights

#### AWS architecture quiz competition

- The game show used **10 question sets** covering simple but practical AWS architecture topics
- Questions focused on cloud concepts, service selection, and solution design thinking
- Some questions were similar to AWS **SAA** exam scenarios, requiring participants to choose suitable AWS services or architecture patterns
- The format helped participants review theory in a more active way than normal reading or presentation sessions

#### Teamwork and quick decision-making

- Each team had to discuss quickly before giving the final answer
- Members needed to divide thinking responsibilities, listen to each other, and agree under time pressure
- The competition format made teamwork more important because even simple questions could become difficult when the team was unsure

#### Game skill: Minimum Risk

- **Minimum Risk** could be used once by each team
- This skill was useful for questions where the team was not fully confident
- If the answer was wrong, the team did not lose points
- If the answer was correct, the team received only half of the question's score
- This skill encouraged teams to evaluate uncertainty before answering

#### Game skill: Star of Hope

- **Star of Hope** could be used once by each team
- This skill was for the question the team felt most confident about
- If the answer was correct, the team received double points
- If the answer was wrong, the team lost double points
- This made the game more strategic because teams had to choose the right moment to take a risk

#### Learning through competition

- The competitive format made the event exciting and easier to remember
- Participants could learn from both correct and incorrect answers
- The questions helped connect AWS theory with real architecture decision-making
- The event encouraged everyone to keep learning cloud fundamentals after the game

### Key Takeaways

#### Cloud Knowledge

- AWS architecture design requires understanding not only individual services but also when to combine them
- SAA-style questions often focus on reliability, scalability, cost optimization, performance, and security
- Choosing the right service depends on requirements such as availability, latency, data storage, traffic, and operational effort
- Basic AWS knowledge becomes more useful when applied to scenario-based questions

#### Team Strategy

- A good team needs both technical knowledge and clear communication
- It is important to discuss quickly but avoid rushing when the question includes important constraints
- Risk-based skills showed that not every question should be treated the same way
- Teams should use confident answers for high-reward opportunities and protect themselves when uncertainty is high

#### Personal Development

- The event helped me recognize which AWS topics I already understood and which areas I need to review more
- Some SAA-related questions showed the importance of reading requirements carefully
- I learned that architecture decisions are often about trade-offs, not only memorizing services
- Practicing with a team helped improve confidence when explaining technical reasoning

### Applying to Work

- Review AWS core services such as compute, storage, database, networking, monitoring, and security
- Practice more SAA-style scenario questions to improve architecture design thinking
- When solving technical problems, identify requirements first before choosing a service
- Discuss options with teammates and explain the reason behind each architecture decision
- Apply risk management thinking when making choices under uncertainty

### Event Experience

Participating in the **"Cloud Architect"** event was a fun and useful experience. The game show format made AWS architecture knowledge easier to review because every question required quick thinking, discussion, and decision-making.

#### Learning in an active way

- Instead of only listening to a presentation, participants had to actively answer questions
- The question sets helped review simple AWS concepts and architecture design principles
- SAA-style questions made the event more practical because they were close to real certification and project scenarios

#### Working with a team

- Each team needed to combine the knowledge of all members
- Team discussion helped reduce mistakes and gave different perspectives for each question
- I learned that communication is very important when the team has limited time to decide

#### Understanding risk and confidence

- The **Minimum Risk** skill taught me how to handle uncertain answers safely
- The **Star of Hope** skill showed the value and danger of overconfidence
- These mechanics made the event more exciting while also teaching a useful lesson about risk management

#### Lessons learned

- Cloud architecture requires both knowledge and judgment
- Reading the question carefully is important, especially for AWS SAA-style scenarios
- Teamwork can improve answer quality when members share reasoning clearly
- Competitive learning can make technical knowledge more memorable and motivating

> Overall, the event helped me strengthen my AWS architecture foundation, practice teamwork, and understand how to make better technical decisions under pressure.
