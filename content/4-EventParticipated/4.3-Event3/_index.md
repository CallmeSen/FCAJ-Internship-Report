### Key Highlights

#### Theory: Agentic AI mindset and architecture

- The session emphasized that an AI agent is not only a chatbot, but a workflow that combines reasoning, tools, context, and action
- A strong architecture should separate concerns clearly: instruction layer, orchestration flow, data/tool integration, and output validation
- Prompt design should be structured, explicit, and outcome-oriented to reduce ambiguity during execution
- Retrieval, grounding, and context management are important to keep responses relevant and reliable

#### Theory: Reliability, security, and operational thinking

- Building AI agents requires attention to reliability, not only model quality
- The event highlighted practical concerns such as access control, data safety, and permission boundaries
- Logging, observability, and evaluation loops are necessary for monitoring agent behavior and improving quality over time
- Responsible AI usage should include traceability and clear guardrails for unsafe or unsupported operations

#### Hands-on Lab: Build and run an agent workflow

- The lab translated concepts into concrete implementation steps, from setup to execution
- Hands-on activities focused on creating and configuring an agent flow, connecting required resources, and running test scenarios
- The workflow showed how to iterate: run -> inspect outputs -> adjust prompts/configuration -> re-run
- The lab reinforced that practical quality comes from repeated validation, not one-time setup

### Key Takeaways

#### Technical Learning

- Agent systems should be designed as **end-to-end workflows**, not isolated prompts
- Prompt quality directly affects consistency, actionability, and safety of outputs
- Tool integration must be explicit, controlled, and aligned with task scope
- Evaluation needs both functional checks (correctness) and operational checks (stability/safety)

#### Engineering Mindset

- Start from requirements and expected behavior before choosing implementation details
- Keep iteration loops short and measurable when tuning prompts or logic
- Treat observability and error handling as first-class components of the solution
- Prefer repeatable patterns so the agent can be maintained and scaled by a team

### Applying to Work

- Apply structured prompt templates instead of ad-hoc prompts in internship tasks
- Use an iterative validation loop when building AI-related features: define criteria -> test -> refine
- Design agent tasks with clear boundaries on tools, data sources, and expected outputs
- Add basic logging and review checkpoints when automating technical workflows
- Document assumptions and constraints so teammates can reuse and improve the same workflow
